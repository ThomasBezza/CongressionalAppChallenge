## Configuration

[render.yaml](render.yaml) defines the Blueprint configuration. Manual creation uses the
same values:

| Setting | Value |
| --- | --- |
| Runtime | Node |
| Branch | codex/hosted-rehearsal-room |
| Instance type | Free |
| Build | `node --test` |
| Start | `node server.mjs --hosted` |
| Health check | `/healthz` |
| Automatic deploys | Off |
| Secret environment value | `HOST_SETUP_KEY`, generated privately in Render (32–128 base64 characters) |

The owner created the initial service through the Render form and generated the secret there.
The Blueprint provides the same settings for recreating the service and generates the secret. If creating manually, use Render's secret generator.
Keep it in Render Environment; do not commit it, paste it into chat, or include it in a
video. The app accepts 32–128 base64 characters. `.node-version` pins the locally tested
Node 24.19.0. The hosted launcher reads Render's `PORT` and `RENDER_EXTERNAL_URL`, binds
`0.0.0.0`, and accepts only that exact Render hostname. Local mode still binds loopback.
Render terminates HTTPS; the Node process receives proxy HTTP. Forwarded headers do not
grant authority. Do not add a custom domain or another instance without updating the
configuration and state design.

Open the service home page and enter the private host key in the password field. A
successful creation remembers it in that tab's sessionStorage. A rejected key clears it
and restores the form. The public page never includes the key; hosted startup logs do
not print it. Share only the participant invitation generated by the host view.

## Free service behavior

Render's free service sleeps after 15 minutes without inbound traffic and normally takes
about a minute to wake. It may restart at other times. Rooms live only in this one Node
process and disappear on sleep, restart or redeploy, as well as end/one-hour expiry.
An old invitation then reports the room unavailable: create a fresh room and invite.
The host setup key stays in the service environment across restarts unless rotated.

Use the Free plan without a payment method for the working $0 budget. Usage limits can
suspend service/builds. No paid plan, database, disk, custom domain or uptime promise is
part of this deployment. A stable address does not eliminate cold starts.

## Repeatable verification

Wake the home page first and wait until it loads. For an optional terminal check, in zsh
enter the key privately (input is hidden), then run:

```sh
read -rs 'HOST_SETUP_KEY?Private host key: '
export HOST_SETUP_KEY
./dev scripts/check-hosted.mjs https://YOUR-SERVICE.onrender.com
unset HOST_SETUP_KEY
```

Use the actual service origin with no room fragment. This creates two clearly named
synthetic participants, admits/readies them, confirms a time request on the other event
streams, ends the room and checks removal. Cleanup is attempted after failures too;
if the service is unreachable a remaining room expires within one hour. The runner
reports a fixed workflow stage and numeric HTTP failures without echoing response bodies,
URLs or credentials. It warns if cleanup could not be confirmed and refuses redirects. It does not verify phone layout or audio.
